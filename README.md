# GOLD DAYZ

Локальный тестовый сервер **DayZ на GTA 5 / RAGE Multiplayer** для отладки механик синхронизации зомби, кастомного инвентаря и карты. Домашняя сборка на `127.0.0.1`, с готовым путём переноса на VDS (Linux/Windows) и публичным открытием.

> **Версия для MTA:SA:** в репозитории рядом лежит самостоятельная сборка того же жанра для **Multi Theft Auto: San Andreas** — зомби, выживание, лут, крафт, торговцы, базы, транспорт и CEF-интерфейс. Код и данные оригинальные (не копия NON-STOP DAYZ), запускается ресурсом `gold_dayz`. Инструкция: [mta/README.md](mta/README.md).

> **Статус:** играбельный dev-сервер. Все 124 тестов и headless-симуляция проходят на чистом Node без `npm install`. Финальная проверка «в игре» (внешний вид зомби/охраны, анимации, ощущения от стрельбы) требует GTA V и клиента RAGE — чек-лист в [docs/CHECKLIST.md](docs/CHECKLIST.md).

## Готовая сборка (без Node.js и без сборки)

```bash
npm run package        # → release/gold-dayz-<версия>/ и release/gold-dayz-<версия>.zip (~210 КБ)
```

Внутри уже собранный клиентский бандл и CEF-UI, dev-`conf.json`, `data/`, сервер, `start.cmd` / `start.sh` и `START.txt` с короткой инструкцией.

Установка:

1. Скачать **server-files RAGE Multiplayer** (Windows или Linux) с https://rage.mp — это единственное, чего нет в архиве (бинарник RAGE не распространяется вместе с gamemode).
2. Распаковать их в папку, например `C:\gold-dayz\`.
3. Скопировать туда содержимое `release/gold-dayz-<версия>/` (файлы не пересекаются).
4. Запустить `start.cmd` (Windows) или `./start.sh` (Linux) — либо `ragemp-server.exe` напрямую.
   `start.cmd` сам переходит в свою папку (`cd /d "%~dp0"`), поэтому работает с любого диска: `D:\GOLD\`, `E:\games\gold dayz\` и т.д.
   Если чего-то не хватает (не распакованы server-files, забыт `packages\`), он скажет, чего именно, и не будет запускаться вхолостую. Сообщения в `.cmd` латиницей — так они одинаково читаются при любой кодировке консоли; русская инструкция рядом в `START.txt`.
5. В клиенте RAGE: **Direct Connect → `127.0.0.1:22005`**.

```text
D:\gold-dayz\ragemp-server.exe      ← из server-files
D:\gold-dayz\conf.json              ← из архива
D:\gold-dayz\packages\gold\index.js
D:\gold-dayz\client_packages\gold\goldclient.js
D:\gold-dayz\server\  shared\  data\
```

### Вход: логин, пароль, персонаж и спавн

RAGE Multiplayer не поддерживает пароли на подключение, поэтому вход делается через **внутренний экран входа** (CEF-UI): игрок вводит логин и пароль, называет персонажа и выбирает точку спавна. По умолчанию **вход по логину/паролю включён** (`auth.enabled: true` в `data/gold.config.json`).

* **Регистрация** — разрешённа: первый вход с новым ником создаёт аккаунт (хеш пароля scrypt+salt, ключ в `storage/accounts.json`).
* **Мин. пароль** — 6 символов. За 5 неверных попыток — блок 15 с.
* **Персонаж** — имя показывается в HUD/чате; профиль (инвентарь, статсы, смерть) сохраняется в `storage/players`.
* **Спавн** — выбор из точек на карте; если не выбрать — ближайшая безопасная.
* **Деньги/кэш-шоп** — нет, только выживание и лут.

Затем игрок проходит `gold:entrySubmit` → сервер спавнит и отдаёт каталог/карту/инвентарь/HUD. Чтобы **отключить** вход (тестовый режим, сразу на спавн), поставьте `"auth": { "enabled": false }`.

Аккаунты по умолчанию хранятся в JSON (`storage/accounts.json`, scrypt+salt). MySQL уже заведена в конфиге (`db`: `gold_dayz`, пароль `GoldDayz1!`) — чтобы пушить аккаунты туда, включите `db.enabled: true` и подключите mysql2 (смотрите [docs/DATA.md](docs/DATA.md)).

* Вайтлист (`access.whitelistEnabled`) — отдельный, ётный уровень: кикает не в списке. Публичный сервер: `announce: true` + `bind: 0.0.0.0` — см. [docs/DEPLOY-VDS.md](docs/DEPLOY-VDS.md).
* Админ-команды по умолчанию — с `127.0.0.1`; для друзей — ники в `admin.names`.

## Как это устроено

```
GTA 5 + RAGE client
        │  CEF UI (client_packages/gold/ui)     client_packages/gold/goldclient.js
        │        ▲  gold:* события                     ▲
        ▼        │                                     │
   client/*.js ──┴────────────── shared/*.js ──────────┘
   (позиции, стрельба, педы)     (чистая логика)
                                        │
                                        ▼
                             server/game.js  ← ядро: зомби, лут, инвентарь, выживание
                                        │
                        server/index.js  ← мост к API RAGE (события, тик, оружие)
```

* `shared/` — чистые модули без API RAGE: инвентарь, выживание, ИИ зомби/охраны, базы, лут-тьеры, протокол снапшотов, RNG, чанки. Их можно гонять в обычном Node.
* `server/game.js` — вся игровая логика, общается с клиентом через адаптер `net` (инъекция). Поэтому мир запускается headless (`npm run sim`).
* `server/index.js` — единственное место, где используются `mp.players`, `player.call`, `player.health` и т.п.
* `client/` — клиентские скрипты; собираются в один файл `client_packages/gold/goldclient.js`.
* `client/ui/` — CEF-страница, копируется в `client_packages/gold/ui/`.

Подробно: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

### Почему зомби — клиентские педы

Серверные «dynamic peds» RAGE требуют назначенного игрока-контролёра и ограничены его физикой. Для отладки собственного протокола синхронизации удобнее и надёжнее держать **авторитетный ИИ на сервере**, а на клиенте создавать педов локально и двигать их по снапшотам. Это даёт:

* полный контроль над интерполяцией и сглаживанием;
* отсутствие зависимости от контролёра и его пинга;
* прозрачную телеметрию (F1) — видно, сколько зомби в снапшоте и как давно он пришёл.

Цена: зомби видны только в радиусе снапшота (320 м), а сервер не проверяет линию видимости для выстрелов (см. «Ограничения»).

## Команды и горячие клавиши

| Клавиша | Действие |
|---|---|
| `I` | инвентарь |
| `M` | карта лут-зон (клик — метка) |
| `E` | подобрать предмет рядом / открыть панель базы, если рядом база |
| `R` | перезарядить оружие |
| `F1` | телеметрия синхронизации (педы, снапшоты, патроны, время) |
| `Esc` | закрыть панель |

**Игроку:** `/pos`, `/stats`, `/inv`, `/map`, `/take`, `/reload`, `/reloadweapon`, `/fill`, `/radio <текст>`, `/base`, `/baseclaim`, `/basegate`, `/basecode <3-8 цифр>`, `/baseunclaim`, `/respawn`, `/suicide`, `/players`, `/report <текст>`, `/help`.

**Админу (localhost по умолчанию):** `/zspawn [n]`, `/zclear`, `/zcount`, `/give <item> [n]`, `/lootzone <zoneId> [n]`, `/tp <x> <y> <z>`, `/tp <playerId>`, `/tpway`, `/god`, `/heal`, `/setstat <key> <value>`, `/kill <id|me>`, `/announce <текст>`, `/metrics`, `/reload`, `/save`, `/kick <id> [причина]`.

`/reload` для админа перечитывает `data/*.json` на лету (предметы, лут, зоны, конфиг) и рассылает новый каталог клиентам — перезапуск сервера для правки баланса не нужен.

### Рабочий цикл

1. Правите `shared/` или `client/` → `npm run build` → перезапуск сервера → заново в игру.
2. Правите `data/*.json` → в игре `/reload` (или перезапуск).
3. Правите `server/` → перезапуск сервера (горячей перезагрузки gamemode у RAGE нет).
4. Перед коммитом: `npm run verify`.

## Конфигурация

Два независимых файла, не путайте:

* **`conf.json`** — настройки RAGE: имя, порт, `bind`, `announce`, `maxplayers`, `stream-distance`, `sync-rate`. Сейчас dev-профиль: `bind: 127.0.0.1`, `announce: false`, `maxplayers: 32`.

`conf.production.example.json` — готовый шаблон для VDS (`bind 0.0.0.0`, `announce true`, сжатие ресурсов). Порядок выкладки: [docs/DEPLOY-VDS.md](docs/DEPLOY-VDS.md).

`data/items.json`, `data/zombies.json`, `data/loot.json`, `data/map.json` — обычный JSON с проверками в `npm run check`. Формат, примеры и типичные ошибки: [docs/DATA.md](docs/DATA.md).

## Синхронизация зомби: цифры

* Лимит одного `player.call` в RAGE — **8192 байта**. Наш внутренний бюджет — **7800**.
* Снапшот несёт до **96** ближайших зомби: ~**4.7 КБ** в худшем случае (проверяется в `check` и тестах), ~**0.7–0.9 КБ** типично.
* Интервал: **50 мс** (< 15 игроков), **100 мс** (загруженный сервер), **200 мс** если рядом нет зомби.
* Клиент интерполирует позицию и заголовок по кратчайшей дуге; сущность без снапшота 3 с удаляется.
* Тик сервера — 100 мс; ИИ «думает» раз в ~400 мс с джиттером, движение пересчитывается каждый тик.

## Ограничения и честные допущения

1. **Нет серверной проверки линии видимости выстрела.** Сервер валидирует дистанцию, тип оружия, патроны и геометрию луча, но не трассирует карту (на сервере RAGE нет физического мира). Стрельба «сквозь стену» технически возможна — для публичного сервера стоит добавить клиентский чек и предупреждения.
2. **Клиентские педы зомби** не участвуют в физике мира: возможны редкие пересечения с машинами/объектами. Позиция авторитетна на сервере, поэтому «убежать» от зомби нельзя.
3. **Снапшоты адаптивные, но не дельта-компрессия**: для 100+ игроков стоит перейти на бинарный протокол или дельты (задел — `shared/sync.js`).
4. **Модель зомби одна** (`u_m_y_zombie_01`) для всех типов; тип передаётся в снапшоте и различается скоростью/уроном, визуальная вариативность — следующий шаг.
5. **Анимации зомби** — гибрид `taskGoStraightToCoord` + `setCoords`; при сильном рассинхроне пед «дотягивается» принудительно. Требует глазной проверки в игре.
6. **Лут — физические объекты, но без отдельных инвентарём/контейнеров**: предметы лежат как `mp.objects` и подбираются мгновенно на `E`. Классические «сумки с инвентарём» — в roadmap.
7. **RAGE-серверные файлы в репозиторий не входят** и не могут входить: скачиваются отдельно с rage.mp; бинарники в `.gitignore`.

## Диагностика

| Симптом | Причина / решение |
|---|---|
| В игре нет HUD и инвентаря | не собран клиент: `npm run build`; проверить `client_packages/index.js` и `client_packages/gold/ui/index.html` |
| Клиент висит на загрузке пакетов | занят порт `22006`, либо в `client_packages` нет `index.js`; смотрите консоль RAGE |
| Зомби «плывут»/дёргаются | F1: большой `snapshot` возраст → смотрите `tickMaxMs`, сеть и `zombies.snapshotRadius`; при высоком пинге поднимите интервал |
| Зомби не появляются | нет игрока в 35–300 м от зоны, либо включён `announce:false` ни при чём — проверьте `/zcount`, зоны в `data/map.json`, `spawnIntervalMs` |
| Ошибка `payload too large` | превышен бюджет 8 КБ: проверьте `npm run check`, сократите описания/число сущностей |
| Команды админа не работают | вы не с localhost; добавьте ник в `admin.names` или включите `admin.enabled` |
| После правки клиента ничего не меняется | старый кэш: перезапустите сервер и переподключитесь |
| Профиль не сохраняется | `persistence.enabled`, права на `storage/players`, ошибки в `logs/gold-dayz.log` |

Подробный плейбук отладки синхронизации: [docs/DEBUGGING.md](docs/DEBUGGING.md).
