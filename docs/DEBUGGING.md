# Отладка GOLD DAYZ

Плейбук для домашней отладки: что смотреть, когда зомби «плывут», инвентарь не открывается или сервер решил, что вы читер.

---

## 1. Инструменты под рукой

| Инструмент | Что даёт |
|---|---|
| `F1` в игре | педы/сущности, возраст последнего снапшота, число зомби рядом, патроны, время, погода |
| `/stats` | HP, кровь, еда, вода, стамина, вес, радиация, кровотечение, счёт |
| `/zcount` | живые/всего зомби и раскладка по зонам |
| `/pos` | координаты, безопасная/токсичная зона |
| `/metrics` | тик (avg/max), снапшоты (шт., средний размер), выстрелы/попадания, игроки, зомби, лут |
| `logs/gold-dayz.log` | всё то же + предупреждения (`[sync]`, `[spawn]`, `[game]`) |
| `npm run sim -- --verbose` | воспроизводимая симуляция мира без GTA |
| `npm run check` | целостность данных и бюджеты пакетов |

Метрики пишутся в лог раз в 30 секунд (`debug.metricsIntervalMs`). Включите подробный лог: `GOLD_LOG_LEVEL=debug` (или `debug.logSnapshots: true` для каждого снапшота).

## 2. Зомби: типовые симптомы

### «Зомби нет вообще»

1. `/zcount` — если 0 живых:
   * игрок должен быть в 35–300 м от центра зоны зомби (`zombies.minSpawnDistanceFromPlayers` / `maxSpawnDistanceFromPlayers`);
   * зона должна существовать в `data/map.json` → `zombieZones` и иметь `max > 0`;
   * глобальный кап: `world.zombieGlobalCap` (120) и суммарный `max` зон (144) — часть зон не заполнится, это ожидаемо;
   * спавн идёт раз в `spawnIntervalMs` (2.2 с) по 3 попытки;
   * в безопасной зоне (`safeZones.noZombies`) спавна нет.
2. Есть в `/zcount`, но не видно:
   * снапшот уходит только в радиусе `zombies.snapshotRadius` (320 м);
   * модель не загрузилась — смотрите `F1` (peds vs entities): если `entities > peds`, модель не создалась;
   * модель не существует в вашей сборке GTA: проверьте `data/zombies.json` → `model` (`u_m_y_zombie_01` есть в ванильной игре).

### «Зомби скользят / дёргаются»

* `F1` → `snapshot` возраст. Норма ≤ 250 мс. Больше — сервер не успевает или сеть тормозит.
* `/metrics` → `tickAvgMs`, `tickMaxMs`. В норме < 2 мс. Скачки > 10 мс — ищите тяжёлый участок (обычно огромное число зомби или запись логов).
* Если дёрганье локальное (педы телепортируются на 2–3 м), значит `setCoords`-страховка срабатывает слишком часто: интерполяция не успевает. Причины: интервал снапшотов 200 мс при видимых зомби (баг конфигурации) или `sync-rate` в `conf.json` слишком низкий.
* Проверьте `stream-distance` в `conf.json` (300 на dev): слишком маленькое значение мешает клиенту держать педов.

### «Зомби бьют сквозь стену / не бьют в упор»

* Удар наносится по расстоянию между серверной позицией зомби и игрока, стены не учитываются.
* Если не бьют в упор — проверьте `attackRange` в `data/zombies.json` (1.6 м) и то, что вы не в безопасной зоне (агрессия там отключена).
* Зомби не атакуют игрока в безопасной зоне (`safeZones.pvp: false`), даже если он стоит на границе.

### «Зомби идут не туда»

ИИ ограничен `radius + 60` от центра зоны. Если вы увели игрока далеко, зомби развернутся на лиш-границе — это норма. Для погони через полкарты поднимите `ZOMBIE.MAX_LEASH_FROM_ZONE` в `shared/constants.js`.

## 3. Синхронизация: как читать цифры

`F1` показывает строку вида:

```
sync: peds 14/ent 14 | snapshot 62 мс | рядом 3 | патроны 11 | час 10.4 | погода OVERCAST | вода нет
```

| Показатель | Норма | Что значит отклонение |
|---|---|---|
| `peds/ent` | равны | `ent > peds` — модель не загрузилась или пед не создался (смотрите консоль клиента) |
| `snapshot` | 50–150 мс | > 300 мс — интервал снапшотов вырос (много игроков/зомби) или сеть лагает |
| `рядом` | соответствует сцене | 0 при видимых зомби — они дальше 60 м (норма) |

Серверный `/metrics`:

* `snapshotAvgBytes` — средний размер снапшота (0.7–0.9 КБ типично, 4.7 КБ потолок);
* `snapshotsSent` — сколько всего отправлено;
* `accuracy` — попадания/выстрелы, полезно для проверки оружия.

### Проверить протокол без GTA

```bash
npm run sim -- --players 8 --seconds 90 --seed 3 --verbose
```

В конце — таблица: тик, зомби, бой, лут, сеть, нарушения лимита. Если `нарушений лимита > 0` — сломали бюджет payload, смотрите `gold:zombies`/`gold:catalog` в `maxBytesByEvent`.

Другой seed = другой мир. Нашли баг — зафиксируйте seed и шаг, воспроизведите в симуляторе, добавьте тест в `tests/`.

## 4. Инвентарь

| Симптом | Проверка |
|---|---|
| `I` не открывает окно | собран ли `goldclient.js` (`npm run build`), нет ли ошибки в консоли CEF (RAGE: `allow-cef-debugging: true`) |
| Окно есть, но пустое | каталог не дошёл: ищите `gold:catalog` в логе клиента, проверьте `npm run check` (нарезка по байтам) |
| Предмет не экипируется | `slot` в `data/items.json` должен быть из `primary/melee/back/armor/mask/hands`, `equipable: true` |
| «Нет места» при пустом рюкзаке | вес: `w / cap` в шапке инвентаря; поднимите `inventory.maxWeightKg` |
| Не снимается рюкзак | верхние слоты (19–24) заняты: сначала переложите предметы |
| Патроны не тратятся | оружие должно быть экипировано в `primary` и перезаряжено (`R`), тип патрона должен совпадать с `weapon.ammoType` |

Все операции идут через `gold:inv`; сервер отвечает полным снапшотом инвентаря. Если UI «залип» — закройте/откройте панель (`I`), состояние перезапросится при следующем изменении (или переподключитесь).

## 5. Смерть, респавн, сохранения

* Умерли — 12 секунд экрана смерти (`spawn.respawnDelayMs`), затем кнопка «Возродиться» (или авт-респавн по таймеру).
* Инвентарь выпадает на землю в радиусе ~1.2 м, через `world.corpseDespawnMs` (10 мин) исчезает.
* Профиль: `storage/players/<имя>.<hash>.json`. Если файл битый — сервер просто выдаст нового персонажа (ошибка в логе).
* Проверить сохранение руками: `/save`, затем отключиться и зайти снова.

---

## 6. Клиент не подключается / зависает

1. Порт `22005` (игра) и `22006` (HTTP клиентских пакетов) должны быть свободны: `npm run doctor`.
2. `client_packages/index.js` и `client_packages/gold/goldclient.js` на месте.
3. После изменения `client_packages` **обязательно** перезапустить сервер и переподключиться (клиент кэширует пакеты).
4. `allow-cef-debugging: true` в `conf.json` — тогда можно открыть DevTools CEF и увидеть ошибки UI.
5. `bind: 127.0.0.1` — подключаться нужно именно к `127.0.0.1`, а не к внешнему IP.

## 7. Логи, которые стоит включить при охоте за багом

```json
// data/gold.config.json
"debug": {
  "logSnapshots": true,
  "logZombieActions": false,
  "metricsIntervalMs": 10000,
  "chatFeedback": true
}
```

`logSnapshots` печатает размер и число зомби на каждого игрока. Не оставляйте включённым на публичном сервере — это тысячи строк в минуту.

## Респавн не срабатывает

* По умолчанию `spawn.autoRespawn = false`: после таймера игрок нажимает «Возродиться» в CEF-экране смерти.
  Нет кнопки или она не нажимается — проверьте, что клиент открыл курсор (`setCursor` в `client/index.js`, обработчик `gold:death`).
* `spawn.autoRespawn = true` возвращает старое поведение: сервер возрождает сам по истечении `spawn.respawnDelayMs`.
* Игрок «застрял мёртвым» — смотрите `/stats <id>`: `alive=false`, `respawnIn` должен убывать до 0.
